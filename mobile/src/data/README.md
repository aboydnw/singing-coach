# Native data adapter

No production defaults, secrets, schema changes, or live-account tests. Configure HTTPS origins with EXPO_PUBLIC_SUPABASE_URL and EXPO_PUBLIC_API_BASE_URL. EXPO_PUBLIC_SUPABASE_ANON_KEY accepts an sb_publishable_ key or a legacy JWT with role=anon and iss=supabase (the server validates the signature). All native Supabase requests and API POSTs use a 45-second abortable deadline, including response bodies, without automatic retries. Native auth uses Keychain storage and PKCE, never browser clients.

Google is off unless EXPO_PUBLIC_GOOGLE_AUTH_ENABLED=true. Before enabling, register the app scheme singingcoach and exact Supabase redirect allowlist entry singingcoach://auth/callback; verify provider configuration and a real-device callback in the beta environment. This switch indicates setup readiness, not an authorization/security boundary. OAuth follows the project's normal account-creation policy. No account or provider changes were made during implementation.

Only sendTake uploads, on the explicit Send action. Persisted journals contain account-scoped request metadata, not audio, access tokens, or local file paths. recoverSend is read-only, including after restart. A server job acknowledgement or matching account-scoped job lookup is required before claiming leaving is safe. A journal that reached uploaded but not POST may explicitly resumeHandoff. An upload interrupted before POST may explicitly discardUnsentUpload (removes the private orphan before clearing metadata).

The current backend has no unique constraint on audio_key and no idempotency key endpoint. A handoff_unknown journal therefore MUST NOT be reposted when lookup returns no job: the original POST could still be running. The app keeps the journal and offers check-again. This fail-safe can strand a request when a POST never reached the server. Resolving that ambiguity needs a backend idempotency contract in a separate change; never clear it automatically or imply retrying Send is safe. Retry and abandon use existing failed-job endpoints and preserve attempt/measurement records.

Native practice contracts validate backend rows and retain raw coaching_json/coaching_md and measurements_json, including partial coaching. Canonical initial learning contracts are mirrored from lib/practice.ts because that file imports the web client; shared selection/schema modules are reused directly. Keep the mirror synchronized until a separate shared-pure-contract extraction is approved.
